第3章 系统需求分析

3.1 可行性分析

3.1.1 技术可行性

本系统采纳了Spring Boot与Vue 3相结合的技术架构，实现了前后端逻辑的清晰分隔。Spring Boot框架在后端表现出色，凭借Java 17语言的强大功能和完善的生态系统，能够高效地支撑业务逻辑处理、数据持久层管理以及系统安全等关键任务。系统采用MyBatis-Plus作为持久层框架，通过其内置的通用Mapper和条件构造器，大幅简化了数据库操作，提升了开发效率。而Vue 3则在前端领域大放异彩，其组件化的开发模式和Composition API，使得构建动态且用户友好的界面变得既快速又直观。

Spring Boot与Vue 3均属于业界广泛认可且成熟的技术栈，它们各自拥有庞大的开发者社区和详尽的文档资源，这为系统的开发提供了坚实的基础。Spring Boot的众多开箱即用功能和丰富的第三方库，简化了后端开发流程；而Vue 3的简洁语法、高效渲染性能以及Vite构建工具的极速冷启动，则让前端开发变得更加轻松和高效。此外，系统集成了MinIO对象存储服务，实现了文件存储与核心业务的物理隔离，提升了系统的响应速度与数据安全性。

在AI技术方面，系统创新性地集成了DeepSeek大语言模型，采用RAG（检索增强生成）架构和SSE（服务器推送事件）技术，实现了流式对话功能。这种技术选型既保证了系统的先进性，又确保了技术的成熟度和稳定性。

3.1.2 操作可行性

本系统界面设计注重简洁性与实用性相结合，操作界面友好直观，无需复杂操作即可轻松上手，适用于各类用户群体。浏览器作为访问系统的唯一工具，无需额外的软件安装或配置，进一步降低了用户的使用难度。

系统基于Spring Boot与Vue 3的架构设计，不仅提升了系统的全面性和完善性，还赋予了系统便捷、高效、友好的使用特性。系统针对不同用户角色（访客、会员、VIP会员、教练、管理员）设计了差异化的操作界面和功能模块，用户在操作过程中能够轻松理解并完成所需功能，从而确保了系统的操作便捷性。

特别是入场核验环节，系统创新性地提出了"系统辅助人工核验"机制，通过会员手机号后四位快速调出系统档案照片进行核比，既满足了无纸化、自助化的入场需求，又大幅降低了引入活体生物识别的高昂硬件成本，实现了显著的降本增效。

3.1.3 经济可行性

从经济角度分析，本系统的开发成本相对较低，但能够带来显著的经济效益。首先，系统采用的开源技术栈（Spring Boot、Vue 3、MySQL等）无需支付昂贵的软件授权费用，大大降低了开发和部署成本。其次，系统实现了健身房核心业务的数字化管理，能够有效减少人工成本，提高运营效率。

通过系统化管理，健身房可以实现会员卡销售、课程预约、入场管理等业务的自动化处理，减少人工操作错误，提升服务质量。AI智能客服的引入，能够提供7x24小时的全天候服务，弥补非营业时间段的服务空白，提升用户体验和场馆的科技附加值，从而吸引更多会员，增加收入来源。

此外，系统的模块化设计和良好的扩展性，使得未来功能的增加和维护成本相对较低，能够为健身房带来长期的经济效益。

3.3 系统非功能需求分析

3.3.1 性能需求

为确保用户操作的流畅性，系统必须在高并发情境下，将页面加载与交互的响应时间控制在3秒以内。这一严苛标准旨在防止系统延迟对用户操作造成任何不便。面对健身高峰期的用户访问高峰，系统需具备每秒至少处理100个并发请求的能力。这一性能指标确保了系统在高峰时段能够持续稳定运行，为用户带来良好的使用体验。

在AI智能客服方面，系统采用SSE（服务器推送事件）技术实现流式响应，确保用户能够实时获取AI的回复内容，提升交互体验。同时，系统采用Vite构建工具，实现极速的冷启动和毫秒级的热更新，提升开发效率和用户体验。

3.3.2 可扩展性需求

为确保系统能够轻松应对用户数量的增加或新功能的添加，软件架构应采取模块化设计。系统采用前后端分离架构，前端基于Vue 3的组件化开发，后端基于Spring Boot的模块化设计，支持独立部署和扩展。

系统支持数据存储与处理能力的持续优化。通过MinIO对象存储服务，实现了文件存储与核心业务的物理隔离，提升了系统的扩展性。同时，系统采用MyBatis-Plus作为持久层框架，支持数据库的读写分离和分库分表，为系统的横向扩展提供了技术支持。

3.3.3 安全性需求

系统应构建一套完善的基于角色的访问控制体系，依据用户角色精确划分功能访问权限。访客角色仅能查看基本信息和使用AI客服；会员角色能够访问个人相关功能；VIP会员角色在会员基础上增加预约教练功能；教练角色能够核销课程和查看我的课程；管理员角色则拥有系统全模块的访问权限。

系统采用JWT（JSON Web Token）进行身份认证和授权，通过拦截器机制防止跨权访问。所有API接口都需要进行权限验证，确保用户只能访问其权限范围内的资源。同时，系统对敏感操作（如退款、核销等）进行二次确认，防止误操作。

在数据安全方面，系统采用HTTPS协议进行数据传输，防止数据在传输过程中被窃取或篡改。数据库密码等敏感信息采用加密存储，确保数据的安全性。
